# 결정 기록

구조, 라이브러리, 코드 규칙처럼 이후 작업의 선택지를 실제로 제한하는 결정만 기록한다. `docs/agent/rules/`는 "무엇을 한다"만 적고, 왜 그렇게 정했는지와 버린 대안은 여기에 둔다. 규칙 문장 끝에 `(결정 003)`처럼 번호로 연결한다.

## 기록하는 것

아래 세 가지를 모두 만족할 때만 기록한다.

- 여러 후속 작업에 영향을 준다
- 합리적인 대안 사이에서 고른 것이다
- 바꾸려면 여러 파일이나 사용처를 같이 봐야 한다

기록하지 않는 것: 한 기능 안의 구현 선택, 값 조정, 파일 이름, PR 설명이나 주석 한 줄로 충분한 것.

## 쓰는 법

- `records/NNN-short-title.md`. 번호는 세 자리 순번, 제목은 영어 소문자와 하이픈
- `template.md`를 복사해서 채운다. 한 기록에 결정 하나. 회의 대화나 파일 목록을 옮겨 적지 않는다
- 상태는 `proposed`(제안, 상대 확인 전), `accepted`(합의됨), `superseded`(다른 결정으로 대체, 링크), `rejected` 중 하나
- 결정이 바뀌면 기록을 지우지 않고 "변경 기록"에 날짜와 이유를 이어 쓴다. 완전히 뒤집히면 새 기록을 만들고 옛 기록을 `superseded`로 바꾼다
- 결정은 보통 PR 리뷰나 이슈 대화에서 확정된다. 확정되면 그 자리에서 기록으로 옮긴다. `.agents/skills/decision`이 초안을 만든다

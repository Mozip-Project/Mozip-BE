# 운영진이 현재 보고 있는 단체는 쿠키로 전달하고, 선택과 전환은 REST로 한다

- 상태: superseded ([결정 008](008-current-organization-on-server.md))
- 기록일: 2026-11-20
- 관련: #39, #41

## 맥락

운영진 한 명이 여러 단체에 속할 수 있다. 운영진 화면은 상단 org-selector에서 고른 "현재 단체" 하나를 기준으로 공고, 지원서, 평가를 보여 준다. 운영진용 요청마다 그 단체를 어떻게 백엔드에 알릴지 프론트와 정해야 했다.

## 결정

- 현재 선택한 단체는 쿠키에 담아 보낸다. 운영진용 GraphQL 필드는 인자가 아니라 요청 쿠키에서 현재 단체를 읽는다
- 단체 선택과 전환은 REST 엔드포인트로 한다. 서버가 소속 여부를 확인하고 쿠키를 심는다
- 쿠키 이름, 경로, 만료, REST 경로는 운영진 이슈에서 구현하며 정한다. 정하면 이 기록의 변경 기록에 적는다

## 근거

- 프론트와 합의한 방식이다
- 로그인 토큰도 쿠키로 다루고 있어 같은 흐름이다. 쿠키를 심는 처리는 REST 쪽이 단순하다 (결정 002)
- 한 번 고르면 이후 요청은 단체 정보를 따로 실을 필요가 없다

## 고려한 대안

- URL로 전달 (경로, 쿼리, GraphQL 인자): 운영진용 요청 전부에 단체 정보를 실어야 해서 정보량이 너무 많아진다

## 영향 범위

- 결정 002의 REST 범위에 단체 선택과 전환이 들어간다
- `docs/agent/rules/graphql.md` 인증 항목
- `AuthCookieManager`와 쿠키 설정 (`auth.cookie`), 운영진 권한 검사(`OrganizationAccessChecker`)가 현재 단체를 받는 자리
- A의 운영진용 필드(공고, 지원서, 평가)도 같은 방식으로 현재 단체를 읽는다

## 변경 기록

- 2026-11-20: 프론트와 합의한 내용을 기록
- 2026-11-20: 결정 008로 대체. 현재 단체는 서버에 저장하고 GraphQL로 고름. 백엔드는 쿠키를 굽지 않음

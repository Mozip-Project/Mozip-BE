# 다른 담당 기능이 필요하면 쓰는 쪽이 인터페이스와 임시 구현을 먼저 넣는다

- 상태: proposed
- 기록일: 2026-11-17
- 관련: #36, #37

## 맥락

A와 B가 도메인을 나눠 맡는데 단체 생성 뒤 무료 체험 시작(A 이용권), 공고 게시 전 운영진 검사(B 단체)처럼 서로의 기능을 부르는 자리가 있다. 상대 순서를 기다리면 작업이 막힌다.

## 결정

- 쓰는 쪽이 먼저 필요하면 쓰는 쪽 PR에서 인터페이스와 아무 일도 하지 않는 임시 구현을 넣는다
- 만드는 쪽이 자기 순서에서 실제 구현으로 교체한다. 임시 구현 클래스에는 `// TODO(A 이용권): ...`처럼 누구 몫인지 적는다
- 양쪽 코드가 다 없는 함수는 미리 만들지 않는다
- 전부 Security가 아니라 서비스에서 부르는 평범한 Spring 빈이다. 로그인 여부는 `GraphqlAuthInstrumentation`이 보고 도메인 권한은 이 빈이 본다

## 근거

- 호출하는 쪽이 시그니처를 정하면 실제로 필요한 인자만 들어간다. 만드는 쪽이 먼저 만들면 안 쓰는 메서드가 생긴다
- 임시 구현이 있어서 PR 단위로 테스트와 배포가 끊기지 않는다

## 고려한 대안

- 만드는 쪽이 먼저 전부 구현: 상대 순서를 기다려야 하고 양쪽 일정이 묶인다
- 이벤트 발행으로 느슨하게 연결: 결과를 바로 써야 하는 호출(권한 검사)에는 맞지 않는다
